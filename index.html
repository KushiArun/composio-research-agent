01 — The Patterns

The headline: dev tools give themselves away for free. Finance makes you ask permission.

  • 01 Developer & infra tools are 100% self-serve — every one of the 10 apps in that category (GitHub, Vercel, Cloudflare, Supabase...) lets you get credentials with zero human in the loop. Finance & fintech is the opposite: only 40% self-serve, the rest gated behind admin approval, a paid plan, or a sales conversation.
  • 02 44 apps are easy wins — self-serve, high agent confidence, buildable today with no outreach required. That's nearly half the list, ready for a toolkit with no negotiation.
  • 03 19 apps genuinely need outreach — gated behind admin_approval or partnership, concentrated in Marketing/Ads (Meta, LinkedIn, Klaviyo) and Ecommerce (Amazon, Squarespace) — platforms that gate on purpose to protect advertiser and buyer data.
  • 04 The most common blocker isn't a bad API — it's undocumented auth. When the agent couldn't reach a verdict, the reason was almost always "the scraped page didn't say how to authenticate," not "this app can't be built." That's a research-tooling limit, not a product limit — and it's exactly what the verification pass below catches.
  • 05 34 buildable apps have no existing Composio toolkit yet. That's a ready-made, evidence-backed backlog — not a guess about what to build next, a list with a docs link for each one.

03 — The Agent

What ran on its own, and where a human had to step in

A Python pipeline (Composio SDK + Groq + DuckDuckGo search) researched all 100 apps without manual lookup. It also failed in three real, logged ways — each one fixed, not hidden.

01
Search
Finds developer docs for each app via web search, retried on connection failure.
02
Fetch
Pulls page text; detects bot-blocked pages and falls back to search snippets.
03
Cross-check
Checks Composio's own toolkit list for an existing integration.
04
Extract
An LLM call turns raw docs text into the 7-field schema, JSON-only, cited.
05
Checkpoint
Saves after every app; a re-run only retries low-confidence records.

Where the agent needed a human

[Gemini] FAILED: 429 RESOURCE_EXHAUSTED — free tier limit: 20 requests/day → 80 apps silently fell back to "unclear" on the first pass. Fixed by: switching the extraction call to Groq (200k tokens/day free tier). [Groq] FAILED: model `llama-3.3-70b-versatile` does not exist (deprecated mid-build) → A second wave of failures, caught only by reading the logs line by line. Fixed by: pinning to `openai/gpt-oss-120b`, verified with a grep before every re-run. [Groq] Rate limit reached — 199,396 / 200,000 daily tokens used → The final ~9 apps (incl. Plaid) hit the wall and defaulted to low-confidence "unclear." Fixed by: trimming the prompt's scraped-content window from 8k → 4k chars, and re-running after the quota window rolled over.
A human (not the agent) chose the verification sample, ran the independent web searches to check the agent's claims, and decided which infrastructure failures were worth fixing vs. accepting as documented limitations. The agent never diagnosed its own quota exhaustion — that required reading raw error logs by hand.
